要把训练好的 PyTorch 模型（.pt 格式）转换成 NCNN 专属的 .param 和 .bin 格式，其实非常简单。
目前有两种最主流且绝对不会出错的方法：方法一（直接官方一行命令导出），以及方法二（通过电脑本地的工具链转换）。

💡 方法一：利用 Ultralytics 官方一键导出（最省心、推荐）

如果你使用的是 YOLOv8 或 YOLOv5 的较新版本，官方早已原生集成了 NCNN 导出支持。你可以在安装了训练环境的电脑上直接运行以下命令：

命令行（CLI）导出：

bash
yolo export model=your_model.pt format=ncnn imgsz=320 half=true
请谨慎使用此类代码。

或者在 Python 脚本中导出：

python
from ultralytics import YOLO

# 加载你训练好的识别人模型
model = YOLO('your_model.pt')

# 一键导出为 NCNN，开启半精度(half=True)，限制尺寸为320
model.export(format='ncnn', half=True, imgsz=320)
请谨慎使用此类代码。
输出结果： 运行后，程序会在当前目录下生成一个名为 your_model_ncnn_model/ 的文件夹。打开它，你会直接看到 model.ncnn.param 和 model.ncnn.bin。把它们名字改掉拿来用即可。

🛠️ 方法二：通过本地编译的 onnx2ncnn 转换（经典工程路线）

如果你手头已经有了导出的 .onnx 文件，就可以直接利用你刚才在 Ubuntu 上成功编译出来的 NCNN 工具链将其转换为 .param 和 .bin。

1. 使用 onnx2ncnn 基础转换

在你先前编译 NCNN 的 ncnn/build/tools/onnx/ 目录下，把你的 yolov5.onnx 拷贝过去，运行：
bash
./onnx2ncnn yolov5.onnx yolov5.param yolov5.bin
请谨慎使用此类代码。
这时已经生成了基础的 .param 和 .bin 文件。

2. 使用 ncnnoptimize 进行融合加速与自动转 FP16（极为关键）

刚转出来的模型包含许多零散、无用的算子。切换到 ncnn/build/tools/ 目录下，使用优化器对模型进行结构融合，它会自动将模型瘦身，并转换为契合骁龙 835 的 FP16 半精度浮点：
bash
./ncnnoptimize yolov5.param yolov5.bin yolov5_opt.param yolov5_opt.bin 0
请谨慎使用此类代码。
最后的 0 代表强制优化输出为 FP16。此时生成的 yolov5_opt.param 和 yolov5_opt.bin 就是你需要的终极部署文件！

🔍 关键技巧：如何查看你的输入输出节点名称？

由于刚才我帮你写的代码中用到了：
• ex.input("in0", in);
• ex.extract("out0", out);
为了防止你运行程序时因为节点名字对不上而导致闪退，请用电脑打开这个可视化工具网站：Netron (netron.app)。
1. 把生成的 yolov5_opt.param 文件直接拖进网页里。
2. 观察最上面的输入节点（通常是一个矩形输入框），点击它，在右侧属性栏查看其 Name。如果是 "images"，你就把 C++ 代码里的 "in0" 改为 "images"。
3. 观察最底部的输出节点（有些 YOLO 会有 3 个不同的输出尺度节点，对应检测大、中、小物体），点击它们并查看右侧的 Name，将 C++ 中的 "out0" 修改为对应的节点名称即可。
1. 你目前训练好的模型是 YOLOv5 还是 YOLOv8？手头目前有 .pt 文件还是已经有了 .onnx 文件？
2. 如果你的网络模型在底层有多路输出（通常有3个输出层节点），在 NCNN 提取结果时需要把这 3 路输出通过代码做一个后处理合并（解码出最后的矩形框）。你的模型是包含了 Detect 导出头（单路输出）还是解耦的分开输出？

这个可以用，但不是首选，且直接转大概率会遇到两个严重的“隐形坑”！
文件名中的 dynamic 代表它的输入分辨率是动态可变的（Dynamic Shape）。如果你用原生的 onnx2ncnn 直接去转它，会在骁龙 835 上引发严重后果：

⚠️ 在骁龙 835 上强跑 Dynamic 模型的两大危害

1. 内存暴涨与耗时不稳定：
NCNN 框架在处理动态输入时，无法在初始化时提前分配固定的硬件缓冲区。这意味着每次相机抓到一个图像帧，NCNN 都要重新在内存里计算、规划、申请所有中间网络层的尺寸，这会导致每一帧的耗时极度不稳定。对于老旧的骁龙 835 而言，这会带来极大的 CPU 带宽负担。
2. onnx2ncnn 转换容易报错：
动态分辨率 ONNX 的结构中包含大量的 Shape、Slice、Gather 算子（用来在运行时动态计算矩阵宽高）。老版本的 onnx2ncnn 工具有很多不支持这些算子，转的时候经常抛出 Unsupported layer type 的错误导致转换失败。

🛠️ 最佳闭坑解决方案：将其“强行固定”为 320x320

既然你在 C++ 里的硬编码配置是 YOLO_WIDTH = 320; YOLO_HEIGHT = 320;，那么我们在将这个 ONNX 转换到 NCNN 的时候，必须强行把它的动态输入“锁死”固定为 320x320 静态度量。
操作非常简单，请直接在你的 Ubuntu 电脑上运行以下两步：

第一步：用 onnxsim 工具固定尺寸并简化模型（核心）

onnxsim（ONNX Simplifier）是一个神器，它可以自动吃掉所有的动态冗余算子，并把输入强行变回静态。
1. 先在 Ubuntu 安装它：bash
pip3 install onnx-simplifier
请谨慎使用此类代码。
2. 执行精简命令（传入你的动态 ONNX，强制灌入 320 静态尺寸）：bash
python3 -m onnxsim yolov5m_dynamic.onnx yolov5m_static_320.onnx --input-shape "1,3,320,320"
请谨慎使用此类代码。
运行后，你会得到一个干净的、没有任何动态开销的 yolov5m_static_320.onnx。

第二步：转换并利用 ncnnoptimize 压榨加速

拿到静态 ONNX 后，再走你刚才编译出的 NCNN 工具链：
1. 基础结构转换：bash
./onnx2ncnn yolov5m_static_320.onnx yolov5m.param yolov5m.bin
请谨慎使用此类代码。
2. 开启 FP16 半精度极限瘦身（这步能让你的模型在 835 CPU 上提速一倍）：bash
./ncnnoptimize yolov5m.param yolov5m.bin yolov5_opt.param yolov5_opt.bin 0
请谨慎使用此类代码。

📝 注意：关于 YOLOv5m 的算力警告

你的文件名显示这是 YOLOv5m（Medium） 模型。
• 我们之前几轮讨论和基准测试（Benchmark）默认是以 YOLOv5n（Nano） 或 YOLOv5s（Small） 这类轻量级模型为基准的。
• v5m 的参数量和计算量是 v5n 的近 10 倍！如果把它放到骁龙 835 上，哪怕按照我们设计的 1秒/0.5秒 检测一次的休眠策略，单次检测的纯耗时也可能会被拉长到 300ms ~ 500ms 左右。
虽然我们加了跳帧控制，1秒跑一次对芯片总体的功耗和发热完全没有威胁，但如果可能的话，依然强烈建议你使用 yolov5n.pt（Nano）或者 Yolo-Fastest 重新导出单类“人”的 ONNX。模型越轻，你的监控响应速度就越快、整体功耗越趋近于零。
